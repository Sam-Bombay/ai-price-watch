AI Price Watch / agent access

Every agent on the machine can read your Workspace

Google put admin agent policies into general availability on 24 November 2026 and named a date on which they stop being optional. Nobody has counted which local agents already hold the credentials.

1 February 2027

That is the date Google gives for technical enforcement of its MCP requirement for AI agents. It is roughly nine weeks away. Every business running coding agents, chat assistants or automated workflows against Gmail, Drive, Calendar or Sheets has until then to know which agents touch that data and under what policy.

What changed, exactly

  • 24 Nov 2026 — Google Workspace MCP servers (Gmail, Drive, Docs, Sheets, Slides, Calendar, Chat, Tasks) and the Workspace CLI went generally available, alongside admin console agent access controls, human-in-the-loop controls, audit logs, and a Workspace API usage dashboard. (Google Workspace Updates, 24 Nov 2026)
  • 1 Feb 2027 — technical enforcement begins on the MCP requirement for AI agents, same post.
  • The CLI includes scoped sign-in — read and update scopes — which means the interesting question stops being "does an agent have access" and becomes "which scope, granted to which agent, on which machine, and who else can read the file it is stored in".

What the inventory returns

A single read-only pass over one workstation. It opens no network connection, sends nothing, and never prints, copies or transmits a secret value — it records the file path, the file mode, the line number and the provider the key belongs to, plus the MCP servers wired into each agent's config.

Run it yourself

The scanner is plain Python, no dependencies, no network calls. It exists at tracker/agent_access_audit.py in the public repo. Run python3 agent_access_audit.py for the text report, or --json out.json for the machine-readable one. If it finds a world-readable key, change the mode today and rotate it when convenient — the window it was open is what matters, not the convenience.
