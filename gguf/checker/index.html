Read a chat template before you run the model

Paste the chat_template out of a GGUF file's metadata. Fifteen patterns drawn from the published indicators of the 22-26 November 2026 Mir2k and timdedid campaigns. Everything runs in this tab — nothing is uploaded, nothing is executed, no request leaves the page.

Where to find it: llama.cpp / gguf-py expose it as metadata["tokenizer.chat_template"]; ollama show --modelfile <model> prints the TEMPLATE block; on Hugging Face it is the gguf.chat_template field of /api/models/<repo>. Comparing two versions of the same file is the highest-signal use — the campaign planted the payload first and armed the template days later.

Limits, stated plainly. This reads text patterns, so it catches a poisoned template and the arming step — it does not see bytes appended after the last tensor, which is where Mir2k hid its executable. It cannot prove a file is clean. For the file bytes, rebuild the GGUF from a trusted quantisation with gguf-radar (MIT) and compare hashes. A template that is absent entirely is also a result: 109 of 350 repositories published in the week to 28 Nov 2026 declared none, and a file whose template you cannot read is a file you cannot clear.
