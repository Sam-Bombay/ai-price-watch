CVE-2026-121481: a critical OpenSSL score, an unfixed pull request, and no known way to trigger it

The NVD published CVE-2026-121481 on 18 November with a CVSS 3.1 base score of 9.8 — network vector, no privileges, no user interaction. The flaw itself: calling EVP_EncodeBlock() with an input length near INT_MAX overflows the encoded-size calculation and writes past the end of the caller's output buffer.

The vendor's own advisory text, in the same record, says: "No path by which an attacker can trigger this has been identified." The fix is an open pull request, openssl/openssl#33652, opened 10 November, still unmerged, and no OpenSSL release since 4.1.0 (23 October) carries it. So the honest state of the world is: a critical number, no patch, and an exploitability claim nobody has backed with a trigger.

Why that still costs you money. If a 9.8 lands in your dependency list, someone eventually asks you to show what you did about it. "We waited" is an answer that survives an audit only if it is written down, dated, and specific to your hosts. That document is the deliverable below — not a scare, a record.

What is actually in scope

  • Only code that links OpenSSL 1.1.1 / 3.x / 4.x. macOS ships LibreSSL at /usr/lib/libcrypto.dylib, a different codebase, not covered by this advisory.
  • Only a call site whose length argument is attacker-influenced and can approach INT_MAX. A literal or sizeof argument cannot reach it.
  • Encoding is a local operation. There is no pre-auth remote trigger in the record — anything claiming otherwise today is selling fear.
